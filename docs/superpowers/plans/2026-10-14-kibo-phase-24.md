# Kibo · Phase 24 : La livraison comme parcours de Kibo (skill `full-delivery`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un run de livraison lancé depuis Kibo **n'est plus bloqué** : le préréglage « Livraison » met l'agent en mode `auto`, avec tous les sous-agents, les règles du projet et les dossiers du skill (`--add-dir`) ; un outil refusé par Claude Code devient une **question de Kibo** avec le bouton « Autoriser et relancer » ; les recouvrements ne bloquent **plus jamais** le `Stop`, le critère « même fichier » disparaît et les fichiers partagés par nature sont hors du critère « bloc ». La livraison devient un **parcours de Kibo** : bouton « Livrer » (consigne `/full-delivery <CLÉ>` écrite par Kibo), ticket parent ⇒ sous-tickets prêts dans l'ordre des dépendances, étapes 0 à 11 du skill posées par `kibo tickets step` et visibles sur la carte, la fiche et la barre, worktree préparé par Kibo avec la recette du projet (copies, ports, commandes `after`), captures d'écran dans la carte de question avec « Valider » / « Demander une correction ». **Une seule source de vérité** : les tickets Kibo sont le plan (CLI `kibo tickets`, `kibo projects`), la file de Kibo est la seule file et les verrous machine de `delivery-slot` sont visibles dans Files d'attente, les projets du registre `full-delivery` s'importent dans les réglages du projet. Spec : **§33** (modèle §35.3, A1 à C3 §35.4 à §35.14, interface §35.15, sécurité §35.16, tests §35.17, faits §35.18, décisions du lead §35.19) ; la CLI `kibo tickets list|get|set` est livrée sur `feat/p24-cli-tickets` (spec §34 ; §33 = Markdown dans la conversation des agents, 0.23.0-alpha.4). **Ajouts d'Adam du 2026-10-14** : les **sous-agents** lancés par le skill (`Explore`, `ecc:code-reviewer`, `general-purpose`…) sont **tracés** sans token (transcriptions `subagents/agent-<id>.jsonl`, hooks, `tool_use`) : type, description, prompt, état, durée, résultat et actions dans le fil du run, une ligne compacte par sous-agent actif dans la barre, un compteur sur la page du run (§35.21) ; **un ticket qui a des enfants ne se lance jamais directement, quel que soit l'agent**, garde côté démon (`TICKET_HAS_CHILDREN`, §35.8). Les écarts constatés au jalon vont en §35.22.

**Architecture:** tout le neuf est **déterministe** : une étape, un refus, un verrou, un import sont des événements (appel de CLI, ligne de transcription, fichier lu, clic), jamais la parole d'un agent. `schema` porte les contrats et les fonctions pures partagées (`isSafeAddDir`, `AGENT_PRESETS`, `deliveryOrder`, `proposeRules`, libellés d'étape) ; `core` la transposition du registre et la détection amendée ; le démon lance `claude` avec `--add-dir` et les règles fusionnées, crée la question de refus au `exited`, joue la recette de worktree, sert les images de question, lit les verrous, importe le registre ; la CLI pose les étapes ; l'interface ajoute « Livrer », le dialogue des sous-tickets, les puces d'étape, la carte de question enrichie, les sections « Livraison » et « Verrous ». Le skill reste à Adam : Kibo ne touche ni `~/.claude/skills/full-delivery` ni le registre.

**Tech Stack:** Bun, TypeScript strict, Zod, Loro, SQLite (`runs.db`, `kibo.db`), React + shadcn/ui + Tailwind, Playwright, fast-check, Biome, faux `claude`, Penpot (plugin MCP). Base : `phase/24` créée depuis `main` @ `8ea95846` (v0.23.0-alpha.3) ; branches `feat/p24-t<n>`, worktrees `.claude/worktrees/p24-t<n>`. Deux branches en cours hors du plan, à ne pas replanifier : `feat/a4-tables` (Markdown et tableaux dans le fil) et `fix/a4-dock-skills` (sous-section recouvrements retirée du dock, colonne de fichiers de la page Skills) ; T1 (`feat/p24-cli-tickets`, CLI `kibo tickets`) est livrée et en relecture.

## Global Constraints

- **Zéro token pour l'état** : une étape (`kibo tickets step`), un refus (ligne de transcription), un verrou (fichier JSON), un import (fichier lu), une validation d'écran (clic) sont des événements déterministes ; aucune parole d'agent ne pose une règle, une étape ni un lien.
- **Jamais de contournement** : `bypassPermissions`, `dontAsk` et `--dangerously-skip-permissions` restent réservés et refusés (`claudeArgs`) ; le mode `auto` est le classifieur ; `--add-dir` est posé par Kibo seul et devient réservé dans `extraArgs` ; `isSafeAddDir` et `isSafeAllowRule` revalidés au lancement.
- **Jamais de blocage** : le `Stop` ne connaît plus les recouvrements ; une alerte est un `additionalContext` sur `allow` ; une recette de worktree en échec rend `WORKSPACE_FAILED` au run, jamais au démon ; un verrou illisible, un registre absent, une image invalide se journalisent.
- **Aucune écriture dans le skill** : `~/.claude/skills/full-delivery/**` et `~/.delivery/**` sont **lus**, jamais écrits ; aucun test n'écrit hors de `tmp()`.
- **Secrets** : `addDirs` jamais `~/.kibo`, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config`, ni la racine `~/.claude` ; recette, `delivery` et `worktree` sont des réglages **locaux** (`project_settings`) jamais synchronisés (`LOCAL_ONLY_META`) ; images de question copiées 0600, servies avec session ; `maskSecrets` sur `cwd` et `label` des verrous.
- **Une seule écriture réservée nouvelle** : `setTicketDelivery` (`COMMAND_WRITES = null`, refusée aux composants, origine `kibo`), sur le modèle de `setTicketProgress` ; `setDeliveryStep` est la seule RPC qui l'émet.
