# Kibo · Phase 31 : cadres du Graphe sans débordement, étapes en attente visibles en cyan, agent de projet en conversation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) un cadre de fonctionnalité du Graphe ne déborde plus : le nombre de lignes du titre est estimé **par mots** (retour à la ligne glouton, même table de glyphes), plafonné à **trois**, la hauteur du cadre suit et le titre est **coupé au nombre de lignes réservées** par un `line-clamp` posé sur un élément interne (spec **§45.1**). (2) Les étapes **en attente** (§41) ne sont plus cachées : nouveau jeton **`--tracking-hold`** (cyan `#0e7490` clair / `#22d3ee` sombre, fond `--tracking-hold-soft` `#ecfeff` / `#082f35`) ; un **segment cyan** par étape en attente dans toute barre d'étapes (Graphe, fiche fonctionnalité, Vue d'ensemble, Planning), **point cyan et ⏸** sur la ligne d'étape du Graphe avec la raison en infobulle, cadre **livré avec attente** qui garde ses étapes en attente visibles et affiche « ⏸ n » dans son en-tête, puces et icônes ⏸ en cyan (fiche fonctionnalité, Kanban, Planning, Vue d'ensemble, Mes tickets) ; les règles de calcul de §41 ne changent pas (§45.2, §45.3). Maquettes **avant le code** : P5b (légende « En attente »), nouveau board « P5b · Graphe · en attente », et les quatre boards « … · en attente » de la phase 29 qui montrent des étapes ou des puces (226 à 229), sombre et clair ; nouveau scénario E2E `silo-graphe` et écran pixel « attente-graphe » ; pixel ≤ 2 % sur l'écran entier sans masque ajouté ; budget UI inchangé (§45.4). Données fictives « Silo » uniquement.

**Goal (suite, §46, ajouté le 2026-10-21 par le lead)** : (3) l'agent de projet devient **une conversation** : la vue « Suivi », le « Résumé du jour », l'onglet « Signaux », les lots remplacés, le menu « ⋯ » et la phrase de pied sont retirés ; le volet montre la conversation de l'agent choisi (bulles d'Adam avec l'heure, réponses Markdown, cartes de lot, lignes de réveil), un message envoyé **s'affiche tout de suite** (« envoi… », « envoyé », « Non envoyé · Réessayer »), un indicateur orange dit « L'agent lit le projet… » ou « En file » ; **« Agrandir »** passe le volet à 720 px avec, à gauche, la **liste des agents** (« + Nouvel agent », puis chaque agent nommé par sa première question, sa date, « n messages », l'agent en cours marqué), rétractable et mémorisée localement ; en étroit (340 px), l'en-tête porte « Liste des agents », « Nouvel agent », « Agrandir », « Fermer » ; un ancien agent s'ouvre en lecture seule (« Ancien agent · <date> », saisie remplacée par « Nouvel agent »). **Le bug du message invisible est corrigé en premier**, à part (T11). Le démon fournit le titre et le nombre de messages de chaque agent (T12). Maquettes **avant le code** (T13) : volet redessiné dans P1 bis v3, « En retard », P6 et « Vue d'ensemble · en attente », nouveau board « P1 bis · Agent agrandi » (écran pixel « agent-agrandi »), références « Agent de projet, volet » et « agrandi, liste rétractée » ; anciens boards du panneau retirés. Entrée ≤ 224 000 ; chunk `project-agent-entry` en baisse.

**Architecture:** rien ne change dans `schema`, `core` ni le démon : `FeatureStep.onHold` (propre ou par dépendance) existe depuis la phase 29 et `featureSteps` le rend déjà. Le travail est **dans les vues** : (a) une **couleur** partagée : le jeton CSS et la valeur `"hold"` ajoutée au type `CaseTone` du SDK (`packages/sdk/src/tracking/timeline-model.ts`) avec une fonction pure `stepCaseTone(step, blocked)` qui place l'attente **avant** le statut ; les trois modèles qui dupliquaient le type (`graph/sprint-lanes.ts`, `planning/planning-model.ts`, `overview/overview-facts.ts`) s'alignent dessus ; (b) le **Graphe** : `frame-geometry.ts` gagne `wrapTitle` et `TitleLines = 1 | 2 | 3`, `sprint-lanes.ts` ne filtre plus rien et garde, pour un cadre livré, les seules étapes en attente ; (c) les **autres barres** cessent de filtrer `onHold` pour leur rendu seulement (les calculs de risque, d'échéance et de « prochaine à finir » gardent les étapes actives) ; (d) les **puces** changent de classes. Les bandes du Planning et la grille « Échéances » (cases posées sur des jours) restent sans attente. Tout vit dans des chunks différés ; `bun run budget` le vérifie.

**Architecture (§46)** : le schéma gagne deux champs **dérivés** sur la session (`ProjectAgentSession.title`, `.messages`), calculés par le démon depuis le journal du run (`sessionDigest`, pure, dans `packages/daemon/src/project-agent/sessions.ts`) ; rien n'est stocké. Dans l'interface, `buildConversation` reste la seule source des items (elle rend déjà `answered` en bulle d'Adam dès l'envoi, et `useRunLog` se recharge sur le sujet `agents`) ; `trackingThread`, `TrackingView`, `TrackingExchange`, `PendingBatch`, `BatchRecap`, `PanelTabs`, `PanelMenu`, `PastSessions` et le dossier `signals/` disparaissent. Le volet se compose de `PanelHeader` (titre, quatre boutons), `AgentList` (colonne ou calque), `ConversationView` (+ bulle horodatée, indicateur de tour, bulles d'envoi en cours), `ComposeBox` (compact seulement), `PastBanner` ; `usePanelLayout` (agrandi, liste) à côté de `usePanelWidth` ; `useOutbox` (envois en cours, fusionnés aux items par `mergeOutbox`, pure). Dans la coque, `ProjectAgentTab` disparaît : le bouton, la pastille et la ligne de signal du fil ouvrent simplement le volet.

**Tech Stack:** Bun, TypeScript strict, Zod, fast-check, Biome, React 19 + shadcn/ui (`@kibo/sdk/ui`), lucide-react (`Pause`), Tailwind 4 (`bg-(--tracking-hold)`), Playwright 1.55 (`toHaveScreenshot`, `maxDiffPixelRatio 0.02`), Penpot auto-hébergé en **Chromium headless** (Playwright, CDP, `receiver.py` 8787 ; le MCP Penpot est souvent injoignable, on passe par l'hôte de plugin), `pypdf` (venv hors dépôt), `xz`.

**Spec:** `docs/superpowers/specs/2026-09-25-kibo-design.md` **§45** (amende §38.7, §41, §44.1 ; s'appuie sur §37.11, §40, §41.1) et **§46** (amende §24.7, §27.7, §38.5 ; s'appuie sur §43). Les amendements techniques faits en même temps que ce plan sont listés dans « Amendements de la spec » ci-dessous.
