# Kibo · Phase 33 : retrait de l'ancien Kibo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** retirer du dépôt, de l'application et des bases de données tout ce que la phase 27 n'avait que masqué (spec **§49**) : l'exécution des agents de ticket (runs, sous-agents, moments, skills, livraison lancée depuis Kibo, doublons, signaux, progression, créations IA, démo, fichiers d'agents, écrans Agents / Files d'attente / Skills / Créations / Changements), l'écosystème de composants tiers (Composants, Sources, Domaines & guidelines, marketplace, `kibo component|market`, `devkit`, `trust`, composants `notes`, `tickets`, `github-issues`, `mcp-source`, `viewer-3d`, moteur de liaison GitHub Issues), l'accès distant et la sync d'équipe (`remote`, `collab`, `sync-server`, réglages Sync et Sécurité, puce de sync) ; **garder** l'agent de projet et tout son historique, le suivi, les maquettes, l'index des notes, l'appairage local de la CLI, les six composants intégrés par le SDK public ; **migrer** `runs.db` et `kibo.db` après sauvegarde ; rendre les instances de composants retirés inoffensives (`RetiredComponent`) ; signer la release avec un certificat auto-signé stable pour que le trousseau cesse de redemander l'accès ; outiller le code mort avec `knip`. Version **`0.33.0-alpha.1`**.

**Architecture:** quatre chantiers, chacun en **deux temps** : l'interface d'abord (elle cesse d'appeler les RPC), le démon et le schéma ensuite (ils cessent de les offrir), pour que `bun run typecheck` reste vert à chaque tâche. (1) **Exécution** : le moteur commun à l'agent de projet est d'abord **isolé** dans `packages/daemon/src/runs/` sans changement de comportement (T2), puis l'interface (T3) et le démon (T4) perdent tout ce qui ne sert qu'aux tickets ; la **migration** (T5) supprime les runs de ticket et les tables mortes après une sauvegarde `VACUUM INTO`. (2) **Composants** : l'interface n'a plus que six composants intégrés et un repli `RetiredComponent` (T6) ; le démon perd le magasin de composants tiers, la marketplace et le moteur GitHub Issues (T7). (3) **Accès distant et sync** : interface (T8), puis démon et serveur HTTP (T9), avec la purge du trousseau et le retour des projets partagés en allocation locale. (4) **Paquets et outillage** : `trust`, `devkit`, `sync-server` et les commandes CLI de composants quittent le dépôt avec la chaîne d'outils embarquée (T10) ; Penpot (T11) et les E2E (T12) suivent ; knip ramène les exports morts à zéro (T13) ; la **signature stable** (T14) est indépendante du reste.

**Tech Stack:** Bun 1.4.2, TypeScript strict, Zod, `bun:sqlite` (`VACUUM INTO`, déclencheurs), fast-check, Biome, React 19 + shadcn/ui (`@kibo/sdk/ui`), Tailwind 4, Playwright 1.55, Tauri 2 (`tauri-action@v0`, variables `APPLE_CERTIFICATE*` du bundler), `codesign`/`security`/`openssl` (macOS), `knip` 5.x (5.88.1 est dans le cache Bun local), Penpot en Chromium headless (`receiver.py` 8787, `.penpot.lock`), `pypdf`, `xz`.

**Spec:** `docs/superpowers/specs/2026-09-25-kibo-design.md` **§49** (amende §6, §7, §8, §10, §17, §18, §20, §26 à §29, §35, §39.1, §39.6.8, §42, §46 ; s'appuie sur §37, §43, §48). Décisions d'Adam du 2026-10-29 reportées en §49 ; choix du lead ci-dessous dans « Décisions d'exécution ».
