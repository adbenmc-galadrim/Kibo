# Kibo · Phase 22 : Agents et skills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** remplacer les profils par des **agents** stockés dans les fichiers Claude Code (`~/.claude/agents/<nom>.md`, `<projet>/.claude/agents/<nom>.md`, agents de Kibo `~/.claude/agents/kibo-<id>.md`), avec spec éditable, sous-agents appelables (`--agents <run>/agents.json`), skills autorisés appliqués par une garde déterministe, un espace **Skills** (cet ordinateur, projets, plugins en lecture seule), un **historique des versions** restaurable, une **écriture concurrente** détectée par empreinte, et des **reviews de skills** laissées par les agents (`skill_review`) que l'utilisateur intègre en diff ou ignore ; migration des profils une fois par machine ; nom de run `projet · agent · ticket` partout.

**Architecture:** `schema` (agent, ref, frontmatter, réglages, skill, review, versions, RPC, action `skill`, moments) → `core` (analyse et réécriture du frontmatter, nommage, composition du `CLAUDE.md` et de `agents.json`, garde pure, nom du run, consignes) → `daemon` (`agent-files/` : découverte, réglages, historique, écriture atomique, conflit, watcher, gabarits, migration ; `skills/` : découverte, usages, reviews, outil MCP ; `agents/` : lancement par `AgentRef`, `--agents`, `--tools`, `--name`, `Skill(id)`, garde) → `ui` (pages Agents et Skills différées, fiche, éditeur avec aperçu, historique, conflit, notes de review, fil) → intégration, E2E, Penpot, jalon.

**Tech Stack:** TypeScript strict, Zod, Bun (`bun:sqlite`, `fs.watch` par `code/watcher.ts`), React 19 + shadcn/ui, CodeMirror 6 (`@codemirror/merge` déjà présent : diff côte à côte et unifié), `renderMarkdownLite` du SDK pour l'aperçu, fast-check, Playwright ; **aucune dépendance nouvelle** (pas de parseur YAML : frontmatter analysé par un lecteur borné, décision 2).

**Spec:** conception **§28.1 à §28.13** (autorité ; amende §5, §7, §8, §20.5, §24.2, §26.4 ; spec agents §3, §5, §7, §8) ; décisions d'Adam du 2026-10-12 (§28.12 : agents de Kibo dans `~/.claude/agents/kibo-*`, nommage lisible, nom de run `projet · agent · ticket`) ; rapport du jalon précédent `docs/superpowers/rapports/2026-10-11-jalon-v0.20.md` ; CLAUDE.md.

## Global Constraints

- **Zéro token pour l'état** : un skill « utilisé » est un `tool_use` `Skill` lu dans la transcription (ou un `PostToolUse` en repli) ; une review est un appel `skill_review` authentifié ; une intégration, une restauration, une copie sont des clics ; un refus est une décision de la garde `PreToolUse`. Aucune parole d'agent ne modifie un fichier (propriété fast-check en T3).
- **Le fichier est la source de vérité** : Kibo n'écrit aucun champ inconnu de Claude Code dans un frontmatter ; les champs qu'il ne gère pas sont réécrits à l'octet près (décision 2) ; un fichier écrit à la main apparaît tel quel.
