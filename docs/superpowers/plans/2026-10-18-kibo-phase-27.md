# Kibo · Phase 27 : suivi seul, création de projet minimale, Emis sur une base neuve Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** troisième volet de « Kibo, outil de suivi » (spec **§39**, demande d'Adam du 2026-10-18 : « faire les choses minimales d'abord »). Kibo **ne lance plus d'agent de ticket** : le réglage « Exécution des agents dans Kibo » disparaît, l'exécution est toujours masquée et **le démon refuse** toute RPC qui lancerait ou nourrirait un run de ticket (`AGENT_EXECUTION_REMOVED`) ; l'agent de projet reste. Un **projet se crée** par un dialogue minimal (nom, clé, début, nombre et durée des sprints, dossier) avec **exactement cinq pages** (Vue d'ensemble, Planning, Kanban, Graphe, Questions) et ses sprints `S1` à `Sn`. **Emis est rebasé** sur un projet neuf par un script qui passe par l'API publique du démon : `F1` à `F15`, étapes `EMIS-1` à `EMIS-n` renumérotées, questions et liens remappés, plan de sprints calculé et écrit dans un rapport avant d'être appliqué. Les **17 constats des critiques UX** retenus par le chef d'équipe (§39.6, commit `620abc91`) sont corrigés : sprint courant unique, retards toujours visibles, CLI qui fait avancer le statut, « bloqué » et « ouvert » uniques, review et CI partout, fiche ticket de suivi, purge de la navigation de l'ère agents, création de projet complétée (client, aperçu, « Pour commencer »), fonctionnalités désignées par `F<n>` et étapes numérotées sans trou, copie et clavier, questions `Qn`, pannes, Kanban, panneau de l'agent, 1024 px, CLI. Chaque écran modifié suit une maquette Penpot (sombre et clair) et une spec pixel. Une **boucle de critique** (§39.4) relance les trois critiques sur la build intégrée jusqu'à trois tours, chaque tour suivi de correctifs, et s'arrête dès qu'un tour ne relève plus aucun constat bloquant ni gênant ; puis jalon **`0.27.0-alpha.1`**.

**Architecture:** le verrou est posé **une fois à la source** : `AppSettingsStore.get()` rend toujours `hidden`, tous les garde-fous existants (`useExecutionShown`, `ExecutionGate`, `agentTracesShown`, `validate.ts`) restent et se trouvent épinglés ; côté démon, un seul module `agents/execution-removed.ts` lève `AGENT_EXECUTION_REMOVED` aux quatre goulets par lesquels passent toutes les RPC concernées (`orchestrator.assign`, `orchestrator.answer` sur un run de ticket, `deliverAnswers`, `allow-resume`), plus les actions de lot `assignAgent` et `deliverAnswers` **à l'application** comme à la proposition. Rien n'est supprimé du code des agents de ticket (§39.1, phase ultérieure) ; seuls le réglage, sa carte et les E2E devenus injouables partent. La création de projet est **côté démon** : `createProject` gagne `setup?: ProjectSetup` ; avec lui, le démon sème les cinq pages et les sprints par les commandes existantes (`addPage`, `addInstance`, `createSprint`), dans la même file que `createProject` ; sans lui, rien ne change (démo, dogfood, scripts, E2E). Le calcul des sprints est **pur et sans horloge** (`sprintPlan`, `nextMonday`, `addDays`), vérifié par fast-check. Le rebase d'Emis est une **extension de `scripts/import-emis`** (`rebase-emis.ts`, dossier `src/rebase/`), trois parties pures (mappage, vitesse, plan de sprints) et deux parties d'I/O (lecture de l'ancien projet par `getProject`, application par `createProject { setup }` et `command`), un `--dry-run` qui écrit `rebase-report.md` et `rebase-plan.json`, un `--apply` qui ne rejoue que le plan relu, un test d'intégration sur un démon temporaire semé d'une copie **fictive de même forme** qu'Emis. Les constats des critiques se répartissent en règles pures de `schema` (sprint courant, retards, `isBlocked`, `isOpen`, libellés `F<n>` et `Qn`), allocation des clés dans `core` (une fonctionnalité créée comme telle prend la clé `F<n>` et ne consomme pas `ticketSeq`), une RPC `declareTicketRef` du démon (la CLI déclenche les mêmes règles que l'observateur), et des tâches d'interface à fichiers disjoints (Vue d'ensemble, Accueil, Kanban, fiche ticket, Questions, coque et navigation, panneau de l'agent, Planning et nouveau ticket). Les maquettes des écrans retouchés sont dessinées d'abord (T9), les specs pixel ferment la phase (T20).

**Tech Stack:** Bun, TypeScript strict, Zod, Loro, SQLite (`kibo.db`), React + shadcn/ui (défaut, plus obligatoire : §39.4) + Tailwind, Playwright 1.55 (`toHaveScreenshot`, `page.clock`), fast-check 4.3.0 (déjà en devDependency de `schema`, `core`, `ui`, `daemon`, `import-emis`), Biome, faux `gh`, faux `claude`, démon temporaire (`Bun.spawn main.ts --port 0`, modèle `import.integration.test.ts`). Base : `phase/27` créée depuis `main` après la fusion de la PR #39 (v0.26.0-alpha.2, `f8988b7b`) ; branches `feat/p27-t<n>`, worktrees `.claude/worktrees/p27-t<n>`. Maquettes nouvelles (T9) : `design/redesign/exports/proposition-{nouveau-projet,kanban,fiche-ticket,questions}-{dark,light}.png`, `proposition-vue-ensemble-v3-*`, `proposition-barre-repliee-*`, `proposition-agent-*` ; cotes « P6 » à « P9 » dans `design/redesign/cotes.md`.

## Global Constraints

- **Zéro token pour l'état** : rien de nouveau ne parle à un LLM ; les refus sont des `KiboError` ; le plan de sprints d'Emis est un calcul pur ; la vitesse observée vient de dates (`gh`), jamais d'un agent.
- **Local-first** : le réglage disparaît de la table `app_settings` par lecture seulement (la ligne existante est ignorée, jamais migrée) ; `createProject { setup }` écrit dans le CRDT par les commandes existantes ; le rapport du rebase et la sauvegarde d'Emis vivent sous `~/Documents/emis/kibo-export-2026-10-18/` et `~/.kibo/backups/`, jamais dans le dépôt.
- **Minimal (§39.1)** : aucun fichier des agents de ticket n'est supprimé ; seuls partent la carte `ExecutionCard`, ses textes, ses tests, le pas `RoleStep` du dialogue et les E2E injouables. Le type `AgentExecution` garde ses deux valeurs (le code qui les lit reste).
- **Un seul chemin de refus** : `AGENT_EXECUTION_REMOVED` est levé par `agents/execution-removed.ts` ; aucune autre chaîne n'invente son propre message ; l'interface traduit le code (« Kibo ne lance plus d'agent de ticket »).
- **Date injectée** : `schema` et `core` n'appellent jamais `Date.now()` ; `nextMonday(today)` et `sprintPlan(setup)` reçoivent leurs dates ; le dialogue lit `fixedNow` du démon comme `FeatureDetail.tsx`.
