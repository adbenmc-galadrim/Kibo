# Kibo · Phase 26 : Vue d'ensemble, graphe par sprint, fiche sprint et report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** second volet de « Kibo, outil de suivi » (spec **§37**, décisions de la phase 26 dans **§38**). Le projet gagne sa page **Vue d'ensemble** (P1 bis : cinq indicateurs, « En ce moment » par les sessions T3 Code, échéances sur quatre semaines, sprint en cours, prochaine à finir, PR en review avec leur CI, questions, activité tirée d'un **journal de suivi** `project_events`, agent de projet en panneau « Suivi »), le **Graphe** passe en **colonnes par sprint** (P5 : fonctionnalités en cadres, étapes listées, livrées repliées), le **sprint a sa fiche** et, à sa fin, l'**agent de projet propose le report** (`list_sprints`, actions de lot `setSprint` et `createSprint`, réveil déterministe une fois par sprint) ; les PR portent leur **état de review** (« changements demandés ») et leur **CI** ; les **sessions T3 Code** sont un signal facultatif (`kibo tickets session`) ; le skill **`update-delivery`** est appuyé par une étape de **retouche** sur un ticket livré ; la disposition **« Bandes »** du Planning devient active. Écrans **P1 bis** et **P5** reproduits **au pixel près** (≤ 2 % de pixels différents sur l'écran entier), sombre et clair, sur la fixture `emis-maquettes` étendue ; **chaque masque de la phase 25 rendu inutile est retiré** (§38.12).

**Architecture:** tout le neuf reste **déterministe** : un événement du journal naît d'une commande appliquée, d'un lot, d'une session ; l'état de review et la CI viennent de `gh` ; une session vient de la CLI ; le report vient d'un lot validé d'un clic. `schema` porte les contrats (`ProjectEvent`, `GithubPrRef.review` et `checks`, `TicketSession`, `DeliveryStep.kind`, `ProjectMeta.description`, actions de lot, entité `project_event`, `sdk.project`) et les fonctions pures (`prChecksTone`, `nextDeliverableStep`, `deadlineRows`, `overviewIndicators`, `sprintEndDigest`, `activeSessions`) ; `core` dérive `session` et `updatedAt` dans les vues et migre la page « Vue d'ensemble » ; le démon enregistre le journal (`events/`), les sessions (`activity/`), lit review et CI dans le poller des PR, réveille l'agent à la fin d'un sprint, étend l'agent de projet ; la CLI déclare les sessions et la retouche ; l'interface ajoute le composant intégré **Vue d'ensemble**, le mode **sprints** du Graphe, la **fiche sprint**, le panneau **« Suivi »**, « Bandes », et complète Tickets, Kanban et la fiche fonctionnalité. **Acceptation pixel** : même méthode qu'en phase 25 (`pixel-kit.ts`, fixture étendue, horloge figée au 16 octobre 2026 14 h 52, `maxDiffPixelRatio: 0.02`, `threshold: 0.3`, image de différence jointe à chaque tâche d'UI) ; **le reviewer refuse toute tâche d'UI sans image de différence sous le seuil**.

**Tech Stack:** Bun, TypeScript strict, Zod, Loro, SQLite (`kibo.db`), React + shadcn/ui + Tailwind, Playwright 1.55 (`toHaveScreenshot`, `page.clock`), fast-check, Biome, faux `gh`, faux `claude`, dépôts git temporaires. Base : `phase/26` créée depuis `phase/25` après le jalon v0.25.0-alpha.1 (T13 et T14 de la phase 25 intégrées) ; branches `feat/p26-t<n>`, worktrees `.claude/worktrees/p26-t<n>`. Maquettes : `design/redesign/exports/`, cotes : `design/redesign/cotes.md` (sections « P1 bis · Vue d'ensemble » et « P5 · Graphe », fournies).

## Global Constraints

- **Zéro token pour l'état** : un événement du journal naît d'une commande appliquée, d'un lot ou d'une session ; `review` et `checks` viennent de `gh` ; une session vient de `kibo tickets session` ; le report est une action de lot validée par Adam ; le réveil de fin de sprint envoie un message, ne déplace rien.
- **Local-first** : journal, sessions et `sprint_ends` dans `kibo.db` (jamais dans le CRDT, jamais synchronisés) ; `review` et `checks` dans la référence de PR du CRDT (données publiques, pas de secret) ; aucun réseau nouveau (`gh pr list` déjà appelé, champs ajoutés au même appel).
- **Rien n'est supprimé** : les contrôles du Graphe passent dans « Options » en mode sprints ; les onglets du panneau de l'agent passent dans « ⋯ » ; la bascule « Bandes » s'active ; le point orange d'un run reste quand l'exécution est montrée.

## Décisions d'exécution

1. **Journal** = table `project_events` de `kibo.db`, append-only, alimentée par l'enregistreur de commandes (`events/recorder.ts`) et le puits `ProjectEventSink` (lots, sessions) ; `kind` et `source` fermés (§38.1) ; rétention 5 000 par projet ; entité `project_event` en lecture seule ; `TicketView.updatedAt` depuis `ProjectActivity.lastEventAt`.

3. **Sessions** : RPC `setTicketSession` (locale), table `ticket_sessions`, expiration 2 h, `ProjectActivity.sessions`, `TicketView.session`, CLI `kibo tickets session <CLÉ|—> start|ping|stop [--tool]` ; déduction par la branche courante sans clé.
