# Kibo · 0.29.0-alpha.2 : réponses sans transmission, suppression d'une question Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** corriger les questions pour la **0.29.0-alpha.2** (spec **§42**, demande d'Adam du 2026-10-19 : « quand on répond à une question on ne peut pas la transmettre ; enlève la transmission, une réponse est directement envoyée à l'agent de projet ; rajoute la possibilité de supprimer une question, sans avoir à l'archiver »). Une réponse enregistrée est disponible pour l'agent de projet sans autre geste (journal `question_answered`, digest du prochain tour, `list_questions`) ; les états « à transmettre » et « transmise · figée », le bouton « Transmettre à l'agent », l'appel `questions.deliver` et la RPC `deliverAnswers` disparaissent ; toute réponse se modifie et se retire ; la carte gagne un menu « ⋯ » avec « Archiver » et **« Supprimer »** (`removeQuestion`, confirmation, journal `question_deleted`, images effacées, numéro `Qn` jamais réutilisé). Trois boards Penpot nouveaux en sombre et en clair ; l'écran Questions au pixel près reste ≤ 2 % sans masque ajouté. Dépôt public : données fictives « Silo » seulement.

**Architecture:** rien de nouveau dans le modèle. La « transmission » était un état posé par le démon (`answer.deliveredAt` / `deliveredRunId`, commande réservée `markAnswersDelivered`) à la reprise d'un run de ticket ; sans run de ticket (§39.1) cet état n'a plus de chemin : on retire tout ce qui le montre ou le propose (composant, coque, SDK, porte du démon, RPC, agent de projet) et on garde les deux champs du schéma pour les données déjà stockées, ignorés partout. La disponibilité d'une réponse pour l'agent de projet existe déjà : `question_answered` au journal (`events/translate.ts`), « Question répondue : … » dans le digest par l'empreinte (`questionPrintOf`), réponse dans `list_questions` ; **aucun réveil** (zéro token). La suppression réutilise la commande publique `removeQuestion` (noyau, `COMMAND_WRITES = "question"`) et ajoute ses effets déterministes côté démon : journal `question_deleted` (traducteur de commandes, question lue dans l'instantané *avant*), dossier d'images effacé (`questionImagesPort.remove`), digest « Question supprimée : <titre> » (titre repris de l'empreinte précédente).

**Tech Stack:** Bun, TypeScript strict, Zod, Loro, fast-check, Biome, React 19 + shadcn/ui (`@kibo/sdk/ui` : `DropdownMenu`, `ConfirmDialog`), Playwright 1.55 (`toHaveScreenshot`, `maxDiffPixelRatio 0.02`), Penpot auto-hébergé en **Chromium headless** (Playwright, CDP, plugin MCP, `receiver.py` 8787), `pypdf` (venv hors dépôt), `xz`.

**Spec:** `docs/superpowers/specs/2026-09-25-kibo-design.md` **§42** (s'appuie sur §23.12, §30.5-30.6, §38.1, §39.1, §39.6.12 ; amende §23.11 point 1, §23.12.3 b, §23.12.4-23.12.5, §30.6).

## Décisions d'exécution

1. **Aucun réveil sur une réponse** (choix du lead, §42) : `WAKE_KINDS` ne change pas ; une réponse n'écrit aucun signal. L'alternative « réveil de l'agent de projet à chaque réponse » coûte un tour (tokens) par réponse sans que rien dans la spec ne le justifie ; la réponse est dans le digest du prochain tour, dans `list_questions` et dans le journal.
