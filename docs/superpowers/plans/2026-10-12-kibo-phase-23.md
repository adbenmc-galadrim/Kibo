# Kibo · Phase 23 : Éviter le code dupliqué entre agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** quand plusieurs agents travaillent sur des tickets différents d'un même projet, chacun **voit** le travail des autres avant de coder (section « Travail en cours sur le projet » à chaque tour, outil MCP `peek_work`), Kibo **détecte** sans token et en continu les recouvrements (même fichier, même export, bloc quasi identique : vérification à chaque écriture et balayage toutes les 5 minutes), l'agent alerté **factorise seul** (alerte dédoublonnée dans l'`additionalContext` du prochain appel d'outil, moment dans le fil des deux runs, rappel au `Stop`), et Kibo **lie seul** les tickets quand une dépendance est constatée (lien « BOU-12 bloque BOU-15 », exception explicite à §24.4, annulable d'un clic). Réglages par projet, recouvrements ignorables, runs `repo` et `worktree` comparés, espaces partagés jamais comparés entre eux. **Dans la même version** (demandes d'Adam du 2026-10-12) : l'agent de projet **modifie, réassigne, rouvre et archive** des questions dans ses lots et lit leur destinataire, l'utilisateur **modifie ou retire ses réponses** tant qu'elles ne sont pas transmises, chaque question a un **aperçu au survol** et une **adresse propre** (défilement et mise en évidence) (§30, T14 à T17) ; Réglages › Domaines & guidelines devient un **explorateur de dossiers** (workspace, puis un dossier par projet) et les **domaines appartiennent à un projet** (migration au premier démarrage) (§31, T18 à T20).

**Base de départ :** la phase 23 part de **`phase/22` fusionnée dans `main`**, après la release `v0.22.0-alpha.1` (PR de phase 22 verte et fusionnée par Adam). Le chef d'équipe crée `phase/23` depuis `main` à ce moment ; toutes les branches de tâche partent de `phase/23`.

**Architecture:** `schema` (recouvrement, lien automatique, réglages, bornes, index, textes français des alertes et de la section, outil `peek_work`, moments `overlap` et `auto_link`, RPC) → `core/overlaps` (pur, testé par fast-check : normalisation, empreintes de lignes et fenêtres, blocs, exports, imports, comparaison par paire d'espaces, rôles, réconciliation et cycle de vie, règle de lien, section « Travail en cours », choix des alertes) → `daemon/overlaps` (clé d'espace de travail, diff git borné, index en cache, store `runs.db`, détection à l'écriture et au balayage, livraison par `PreToolUse`, rappel au `Stop`, `peek_work`, lien automatique par `addLink` avec l'origine `kibo`, RPC, agrégats) → `ui` (moments dans le fil, Activité, puce de la barre, page du run « Travail en parallèle », dialogue « Voir les fichiers », badge « par Kibo », réglages « Doublons entre agents », « Ce que reçoit l'agent ») → intégration, E2E, Penpot, jalon.

**Tech Stack:** TypeScript strict, Zod, Bun (`bun:sqlite`, `node:crypto` dans le démon seulement), git par `runGit` avec délai, React 19 + shadcn/ui, CodeMirror 6 (`CodeEditor layout="split"` déjà présent), fast-check 4.3, Playwright ; **aucune dépendance nouvelle** (pas de jscpd, pas de parseur : empreintes de lignes normalisées et expressions régulières, décisions 1 et 2).

**Spec:** conception **§29.1 à §29.14** (autorité) ; **§30** (questions : actions de lot, destinataires, réponses modifiables, aperçu au survol, navigation vers une question ; demande d'Adam du 2026-10-12, tâches T14 à T17) et **§31** (page Domaines & guidelines en dossiers, domaines par projet ; demande d'Adam du 2026-10-12, tâches T18 à T20), livrés dans la même version ; (§29 : amende §23.12.2, §24.4, §24.5, §26.2, §26.4, §28.5 ; spec agents §3) ; décisions d'Adam du 2026-10-12 (§29, en tête : couche 1 section + `peek_work`, couche 2 vérifications continues par `PostToolUse` et balayage 5 min avec alerte par `additionalContext` dédoublonnée, factorisation par l'agent seul, lien « bloque » posé par Kibo et annulable, agent de projet non nécessaire) ; §29.15 ajouté par ce plan (décisions du lead dev) ; rapport du jalon précédent `docs/superpowers/rapports/<date>-jalon-v0.22.md` ; CLAUDE.md.

## Décisions d'exécution

1. **Empreinte injectée** : `core/overlaps` ne lit ni `node:crypto` ni `Bun` ; toute fonction qui hache reçoit `hash: Hasher = (text: string) => string` (SHA-256 hexadécimal, 64 caractères). Le démon fournit `sha256Hex` (`daemon/src/overlaps/hash.ts`, `node:crypto`) ; les tests de `core` importent `createHash` de `node:crypto` dans le fichier de test. **Empreinte de ligne** = 16 premiers caractères de `hash(ligne normalisée)` ; **fenêtre** = `hash(6 empreintes de ligne consécutives jointes par "\n")` tronqué à 16 ; **clé de bloc** = `block:` + `hash(empreintes de ligne du bloc jointes par "\n")` (64 caractères). La spec parle de « SHA-256 des lignes normalisées » : passer par les empreintes de ligne est équivalent (même suite de lignes ⇒ même suite d'empreintes ⇒ même clé) et évite de garder le texte normalisé en mémoire. Interprétation signalée.
2. **Index par lignes** : `IndexedFile.lines: LineHash[] = { line: number (numéro dans le fichier courant), hash: string (16), chars: number }` pour les lignes **ajoutées** normalisées ; les fenêtres sont dérivées à la comparaison (`windowsOf(lines)`), jamais stockées ; `exports: string[]` et `imports: ImportRef[] = { spec, names, line }` (spécificateurs relatifs seulement) par expressions régulières sur les lignes ajoutées brutes ; `hash: Sha256 | null` du contenu courant (`null` si supprimé) ; `status`, `added`, `removed` lus de `git diff --numstat`. Un fichier au-delà de 20 000 lignes ajoutées garde `lines: []` et `clipped: true`.
3. **Blocs** : algorithme jscpd-like sur les fenêtres : index `Map<windowHash, positions[]>` de B ; pour chaque fenêtre de A présente chez B, extension tant que les empreintes de ligne suivantes coïncident (dans A et dans B, même ordre) ; les positions visitées sont marquées pour ne pas rapporter un sous-bloc ; un bloc est retenu si `lines ≥ settings.minLines` et `chars ≥ 160` ; un bloc dont les deux côtés sont au même chemin avec la même empreinte de fichier est écarté (reprise, §29.5). Normalisation (`normalizeLine`) : trim, espaces internes réduits à un ; lignes vides, lignes de commentaire seul (`//`, `#`, `/*`, `*`, `*/`, `<!--`, `-->`) et lignes de ponctuation seule (uniquement des caractères de `{}[]();,`) **retirées** (elles n'ont pas de `LineHash`).
4. **Rôles** : `assignRoles(candidate, a: WorkspaceRun, b: WorkspaceRun, writer: string | null)` : si `writer` est la clé d'un des deux espaces (vérification déclenchée par une écriture) ⇒ `other` = l'écrivain ; sinon `owner` = l'espace dont le **plus vieux run** a le plus petit `(startedAt, runId)`. `WorkspaceRun = { key, runId, startedAt }` = le run le plus ancien de l'espace (§29.9 : un espace partagé est adressé au plus jeune côté `other` et au plus vieux côté `owner` ; le moment est écrit dans le fil de tous ses runs).
5. **Réconciliation** (`reconcile(open, findings, ignored, scope, now)`) : `scope = { kind: "sweep", project } | { kind: "file", workspace, path }` ; en `sweep`, tout recouvrement ouvert du projet absent des findings est réglé ; en `file`, seuls les ouverts dont `detail` cite `path` du côté de `workspace` et absents sont réglés ; une clé `kind:key` de `ignored` est écartée ; un finding dont la paire `(kind, key, ownerWorkspace, otherWorkspace)` est déjà ouverte va dans `touch`. Le store applique : `create` ⇒ ligne + moment `overlap` dans le fil de tous les runs des deux espaces + file de livraison ; `resolve` ⇒ événement `resolved` (le fil n'écrit **pas** de moment de plus : l'état « Réglé 14:52 » est lu par `overlaps.list`, §29.5) ; `touch` ⇒ `last_seen_at`.
6. **Store** (`runs.db`, seconde connexion sur le modèle de `openSignalStore`) : `run_overlaps` (colonnes du modèle + `last_seen_at`) protégée par des triggers `BEFORE UPDATE OF id, project_id, kind, key, owner_run_id, other_run_id, owner_workspace, other_workspace, detail, first_seen_at ON run_overlaps ⇒ RAISE(ABORT, 'append-only')` et `BEFORE DELETE` : seul `last_seen_at` est modifiable ; `UNIQUE` partiel sur les ouverts impossible sans colonne de statut ⇒ colonne `open INTEGER` (1 à la création, mise à 0 par le même chemin que l'événement `resolved`/`ignored`, dans la même transaction) avec `CREATE UNIQUE INDEX … WHERE open = 1` (le trigger `UPDATE OF` n'inclut pas `open`) ; `run_overlap_events { overlap_id, type: "delivered" | "resolved" | "ignored", role: "owner" | "other" | null, by, at }` append-only ; `run_overlap_ignores { project_id, kind, key, by, at, active INTEGER }` (réactiver ⇒ `active = 0`, modifiable) ; `run_auto_links` append-only + `run_auto_link_events { auto_link_id, type: "cancelled" | "removed", by, at }`. `Overlap.deliveredAt` = premier événement `delivered` de rôle `other`, `ownerDeliveredAt` = rôle `owner` (ajout au modèle, interprétation signalée). Repli `foldOverlap(row, lastSeenAt, events)` dans `@kibo/schema`.
7. **Clé d'espace de travail** : `workspaceOf(run: RunView, git): Promise<WorkspaceRef | null>` : `null` si `run.kind !== "ticket"`, si `run.cwd` est nul, si le libellé `run.workspace` n'est ni `repo` ni `worktree:*` (`isolated`, `projet`), si `git rev-parse --show-toplevel` échoue ou si le dossier a disparu ; sinon `{ key: realpath(cwd), kind: "worktree" | "repo", worktreeName: basename(cwd) | null, baseHead: run_traces.base_head }`.
