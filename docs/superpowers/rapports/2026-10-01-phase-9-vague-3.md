## Risques et suivis

- `commitDrop` (Kanban) : si l'écriture de `order` échoue après `setStatus`, le message « Impossible de déplacer KIB-n » est trompeur (le statut a changé, l'ordre se recale au prochain événement).
- `fileTicket` n'émet pas `{ topic: "config" }` : l'usage des domaines peut rester périmé pour les tickets de la boîte ; `restoreBoth` recharge même sur `NOT_FOUND`.
- Mise à jour CRDT envoyée avant un échec de transaction (même fenêtre que les commandes, préexistant).
- `Shell.tsx` à 301 lignes et `sdk/mock.ts` à 315 : extraire à la prochaine modification.
- Tests manquants : `refreshMarketSource` (erreur, source désactivée, retirée) ; `FileTicketDialog` pour `CONFLICT`, `NOT_FOUND` et l'erreur générique ; échec de suppression dans la boîte ; `subscribePref` externe ; Échap hors champ ; Annuler sur retrait de file et suppression de profil (Agents).
- Mineures restantes : compteur « n / N » sans `role="status"`, état `copied` qui ne revient pas à `idle`, squelette `aria-busy` sans `role="status"`, ancêtre de contexte non atténué dans l'arbre, `missing` vrai pour un run tout juste lancé, `MarketCatalogSection` avec identifiant brut, `fr-security` « sandboxés », `fr.settings.components` inutilisée, `localStorage.clear()` redondant, `article` focusable en lecture seule (Kanban), dialogue de rattachement fermé sans message si le ticket disparaît.
- Coque : `handle.exit(1)` plutôt que `process::exit`, timer de « Réessayer » non annulé, `main.rs` 406 lignes à découper (`startup.rs`).
- Correctif `--drag-x/--drag-y` du Kanban couvert seulement par le glisser E2E de T44 ; le glisser depuis le titre de la carte n'a pas de test (seule la ligne de clé est saisie en E2E).
