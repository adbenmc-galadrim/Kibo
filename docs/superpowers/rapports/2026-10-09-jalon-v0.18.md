## Écarts et points ouverts

- **Digest** : les 50 premiers changements dans un ordre fixe (runs, tickets, questions, notes), pas les plus récents : sans journal d'événements, aucune récence n'est calculable (amendement de §24.5). Les runs de projet sont exclus de l'empreinte.
- **`propose`** se fie aux empreintes de notes du début du tour : une note modifiée pendant le tour ne peut finir que « Périmée », jamais écrasée.
- **« Ouvrir la mémoire »** ouvre la vue Notes : aucune API n'ouvre encore une note par son chemin.
- **Lecteur** : couvert par un test d'intégration sur un vrai projet partagé (rôle lecteur), pas par l'E2E (un seul démon).
- **403 d'un run de ticket sur `/agent-mcp`** : couvert en unitaire seulement.
- Fichiers déjà au-dessus de 300 lignes avant la phase : `components/service.ts` (338), `daemon.ts` (325, en baisse).

## Risques

- `maxParallel` du profil Agent de projet est global : deux projets ne pensent pas en même temps.
- Instantané d'un très gros projet : borné par section, mais le premier tour coûte plus de tokens.
- Notes modifiées hors Kibo entre proposition et validation : détectées par empreinte (périmée), pas par date.
