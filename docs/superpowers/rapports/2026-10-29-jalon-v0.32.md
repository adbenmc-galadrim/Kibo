# Jalon 0.32.0-alpha.1 : écrire depuis la CLI (phase 32)

Plan : `docs/superpowers/plans/2026-10-29-kibo-phase-32.md` · Spec : conception §48. Origine : un retour d'expérience du 2026-10-29. Une mise au plan d'environ 110 écritures (fonctionnalités, tickets, sprints, dépendances, questions) avait dû rétro-concevoir `/api/rpc`, faute d'écriture dans la CLI.

## Livré

- **Écritures** : `kibo features create`, `kibo tickets create|update|move|link|unlink`, `kibo sprints create|update|assign`, `kibo questions list|add|answer`. Les clés (`SILO-12`, `F3`, `S2`) sont résolues côté CLI et l'acteur est l'humain appairé. Les textes se lisent depuis `@fichier` ou `@-`, et `--append`/`--prepend` complètent une description.
- **Plan d'un bloc** : `kibo plan apply <fichier> [--dry-run]` lit un YAML (`Bun.YAML`) ou un JSON d'actions `ProposedAction` restreintes, avec références `new:<n>`.
  - La validation complète passe avant toute écriture (`validateBatch`).
  - Les clés futures sont prédites (`predictKeys` + `keyForecast`).
  - L'application est séquentielle et s'arrête à la première erreur, avec la liste de ce qui a été créé.
  - Côté démon, les RPC `previewPlan`/`applyPlan` sont servies en local seulement. L'exécution d'une action est partagée avec les lots de l'agent de projet (`apply-actions.ts`), et `createTicket.feature` est ajouté aux lots.
- **Lecture** : `kibo plan export` (Markdown déterministe par sprint) ; `kibo tickets list --feature/--label/--fields`.
- **API brute** : `kibo rpc '<json>'`, appairage et fermeture de session gérés.
- **Erreurs actionnables** : le noyau dit « a step inherits the sprint of its feature: set it on F1 », et la CLI traduit les erreurs connues (« Le sprint d'une étape vient de sa fonctionnalité : posez S1 sur F1. », cycle, lien existant, lecture seule…).
- **Documentation** : `docs/cli.md` (commandes, codes de sortie, appairage `/api/pair` + cookie + `Origin`, méthode `command`, sens des liens, ticket racine, sprint posé sur la fonctionnalité) et `docs/cli-plan-exemple.yaml`, validé par test.
- **Garde-fou** : un prénom réel dans un test du Graphe (arrivé avec #56) faisait échouer `scripts/forbidden-terms` sur `main`. Il est remplacé.

## Vérification

- `bun run check`, `bun run typecheck` et `bun test` passent sur `phase/32`. La CLI compte 351 tests, dont 10 d'intégration contre un vrai démon.
- Parcours fait à la main sur un démon jetable (projet fictif « Silo ») :
  - création d'un sprint, d'une fonctionnalité avec sprint, de deux étapes (dont une facultative) ;
  - lien `SILO-1 --blocks SILO-2`, cycle refusé avec la bonne phrase, sprint sur une étape refusé avec la consigne ;
  - `--append` et question avec options ;
  - `plan apply --dry-run` puis `apply` de l'exemple : les clés prédites (F2, SILO-3 à SILO-5) sont égales aux clés créées ;
  - un plan invalide est refusé sans rien écrire ;
  - `plan export` reflète tout.

## Écarts

- §48.6 avait les places inversées dans la phrase du cycle. Elle est corrigée : pour `link A --blocks B`, la phrase est « A dépend déjà de B ».
- Un plan ne rend pas une étape facultative : il faut passer par `tickets create --optional`.
- `--project` est facultatif pour `plan apply` et les écritures quand le dossier courant ou le préfixe de clé désigne le projet.
- Le détail par tâche est dans §48.7 et dans la section « Écarts » du plan.

## Risques

- **Pas de transaction** : un plan arrêté en cours de route laisse ce qui précède écrit. La sortie le dit, mais une relance recrée les tickets (pas d'idempotence par rapprochement).
- **Prédiction des clés non réservée** : une écriture concurrente entre `--dry-run` et `apply` décale les clés. Une racine existante sans clé courte qui reçoit une étape peut aussi fausser la prédiction.
- **`--append`/`--prepend` sans garde** : la lecture puis la réécriture peuvent écraser une modification concurrente (`--if-version` hors périmètre).
- **Hors périmètre**, à reconsidérer sur un prochain retour : en-tête de description calculé ou `tickets lint`, outils MCP en écriture hors des agents Kibo.
