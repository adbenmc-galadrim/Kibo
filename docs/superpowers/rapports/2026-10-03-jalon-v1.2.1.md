## Décisions écrites dans la spec, à valider par Adam

- **Agents §14.4 « Files d'attente »** : un run remis en file distingue une réponse (il avait posé une question) d'un simple message ; la `question` reste dans la vue jusqu'au `spawned`.
- **Agents §14.6** : un run ouvert lors d'un redémarrage du démon est clos en `failed`, daté de son dernier événement.

## Écarts et points ouverts

- T4 : le cadre de l'aperçu a une bordure de 1 px ; l'E2E mesure donc 558 px pour une boîte de 560 px. Bordure conservée.
- `question` résiduelle sur un run `failed` (remarque du lead) : un run qui avait posé une question, puis a échoué, puis reçoit un message affiche « réponse reçue ». Défendable (la session reprend sur la question) ; à trancher si la lettre de §14.4 doit primer.
- Une sortie enregistrée en `starting` avec une question gardée n'arrive pas en pratique (`spawned` est appliqué avant l'attente de fin) ; durcissement possible dans une prochaine phase.
- Toujours ouvert : `run_done` à chaque fin de tour (décision d'Adam).
