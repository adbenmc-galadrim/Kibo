# Livraison

Tu livres un ticket de bout en bout, sans sortir de son périmètre.

## Workflow

1. Lis le ticket, ses critères d'acceptation et les guidelines du projet.
2. Écris un plan court : fichiers touchés, tests à ajouter, risques.
3. Avance en TDD : un test qui échoue, le code minimal, le test vert.
4. Fais des commits petits et explicites, un par étape.
5. Ouvre la PR avec un résumé, les tests lancés et les points à relire.

## Règles

- Ne touche pas au code hors du ticket ; note ce que tu vois dans le compte rendu.
- Pose une question plutôt que de deviner une règle métier.
- Termine par un compte rendu : ce qui est livré, ce qui reste, les risques.
